# 交给用户前的自查清单

每做完一课，运行 `node tools/check.mjs --only <跨页号> --demo`，**打开 `check-shots/` 里的截图逐条看**。文件名：`k00-cover.png` 合着的封面，`kNN.png` 默认视角，`kNN-exI.png` 第 I 个装置，`kNN-demoJ.png` 演示第 J 个镜头。`report.txt` 是错误和警告。

## 必须全部做到

- [ ] `report.txt` 里错误为 0。
- [ ] 插图立起来了，没有空白的右页。
- [ ] 装置够大：默认视角下占右页插图区一半以上的宽度，主体清楚可辨。
- [ ] 没有东西互相穿插（球陷进坡里、纸签插进物体、旗杆穿过杯子）。
- [ ] 纸签、仪表架、读数都不压住装置，也不互相重叠；文字没有被切掉。
- [ ] 至少一个能拖或能点的东西，操作后读数立刻变化。
- [ ] 读数、手写数据、翻盖解释、预测答案、测验答案和模型算出的值一致（自己挑两个数手算核对一遍）。
- [ ] 挑战能完成，完成时盖章。
- [ ] 演示 5 个镜头每张都对准了要看的东西，字幕和画面对得上；最后一张回到默认视角。
- [ ] 每个装置（`-exI`）都单独看过。
- [ ] 全书颜色含义一致，并且写进了 `config.legend`。

## 常见坑

- **`build()` 里用到的字段没有初始化**：`build()` 在构造函数中调用，class fields 那时还没赋值。字段都在 `build()` 里建，或者用 `this.x ??= …`。
- **静态线加了但没 `sched`**：每条 `this.ink.add` 都要 `sched: this.pen.next(长度)`，否则线不会被“画出来”。
- **自己 new 的 `InkLathe` / `MeterTube` 看不见轮廓**：忘了 `this.lifters.push(x)` 或 `this.deferred.push(() => x.build())`（`MeterTube` 是 `buildLines()`；用 `this.rack()` 就不用管）。
- **球没有轮廓**：`InkSphere` 要 `this.lifters.push(球)`。
- **东西跑出底座板**：rect 没把仪表架、纸签、挑战卡包进去。
- **装置太小**：rect 太宽导致 scale 只能 1.0。把装置做紧凑、往高里长，scale 提到 1.3 以上。
- **演示镜头一会儿近一会儿远**：用 `this.near(x, y, z, off)` 取景，`off` 用世界毫米，不随装置放大变。
- **演示里换装置没反应**：`act` 里用 `this.switchExhibit(i, true)`。
- **开关点了没反应**：重写了 `onSwitch` 却没把 `'ex'` 交给 `super.onSwitch`。
- **逐帧积分的误差露馅**（例如坡底速度显示 2.96 而公式是 2.97）：关键时刻用公式算准确值。
- **`$...$` 出现在纸签、手写数据或字幕里**：这些地方不排公式，改用 Unicode（√、²、₀、θ）。
- **不认识的公式命令被吞掉**：`\frac`、`\cos` 不支持，用 `a/b`、`\rm{cos}`。
- **左页放不下**：删字，而不是缩小字号；按 `content-format.md` 的字数预算写。
- **英文书出现中文**：`lang: 'en'` 后，你自己写的纸签、手写数据、`toast` 也要用英文。

## 交给用户时说清楚

- 怎么本地打开（`npm run dev`，网址 `#数字` 直接翻到某个跨页）。
- 怎么发布（`npm run build`，把 `dist/` 放到任意静态托管，如 GitHub Pages、Netlify、Vercel）。
- 还剩哪些警告、为什么保留。
- 哪些内容是你补充的、哪些数值做了简化（也写进 `config.notes`）。
